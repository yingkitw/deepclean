# Dependency Cleaning Feature

## Overview

The dependency cleaning feature allows `deepclean` to detect and optionally remove unused dependencies from your Cargo projects. This helps keep your `Cargo.toml` files clean and reduces build times.

## How It Works

### Detection

`deepclean` uses **built-in detection** — no external tools required (implemented in `src/deps.rs`):

1. **Manifest parsing**: reads `[dependencies]`, `[dev-dependencies]`, and
   `[build-dependencies]` tables from `Cargo.toml`
2. **Source scanning**: scans `src/`, `examples/`, `tests/`, and `build.rs`
   (each file read once) for usage patterns:
   - `use <dep>::…` / `use <dep>;`
   - `crate::<dep>` paths
   - `<dep>::` path expressions
   - `extern crate <dep>`
   - `<dep>!` macro invocations
   - `#[<dep>` attribute macros
3. **Name normalization**: dashes and underscores are treated as equivalent
   (`tokio-util` matches `tokio_util`)
4. **Manifest cross-check**: feature and alias references inside `Cargo.toml`
   itself count as usage

### Removal

If `--remove-deps` is specified, `deepclean` removes unused dependencies using:

- **cargo-remove** (from cargo-edit): safely removes dependencies from `Cargo.toml`
  - Preserves formatting and comments where possible

## Usage

### Basic Detection

```bash
# Check for unused dependencies (report only)
cargo deepclean --clean-deps

# Check with verbose output
cargo deepclean --clean-deps --verbose
```

### Detection and Removal

```bash
# Remove unused dependencies (--remove-deps implies --clean-deps)
cargo deepclean --remove-deps

# Preview what would be removed (dry-run: report, no removal)
cargo deepclean --remove-deps --dry-run
```

### Combined with Target Cleaning

```bash
# Clean both target directories and unused dependencies
cargo deepclean --clean-deps --remove-deps
```

## Installation Requirements

### For Detection

None — detection is fully built in.

### For Removal

```bash
cargo install cargo-edit  # Provides the cargo-remove command
```

Without `cargo-remove`, dependencies are still detected and reported, but not removed.

## Limitations

1. **False Positives**: detection is text-heuristic based, so some dependencies
   might appear used (keeping them safe) or unused (flagged wrongly) when:
   - Usage is generated by complex macros or build scripts
   - The dependency is loaded dynamically rather than linked
2. **Workspace Handling**:
   - Discovery collapses workspace members to the workspace root, so only the
     root manifest is checked; member `Cargo.toml` files are not analyzed
   - `[workspace.dependencies]` inheritance is not resolved
3. **Removal Tool**:
   - If `cargo-remove` is not installed, dependencies are detected but not removed

## Best Practices

1. **Always use `--dry-run` first** to see what would be removed
2. **Review the output** before removing dependencies
3. **Test after removal** to ensure nothing breaks
4. **Use version control** so you can revert if needed
